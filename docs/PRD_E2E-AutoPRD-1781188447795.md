## 3. 背景与目标

### 3.1 背景

项目需要在统一默认三端架构上交付一个可运行的旅游产品预订系统。管理端负责旅游产品、分类、订单、用户与运营内容管理；移动端面向游客提供产品浏览、搜索筛选、详情查看、下单预约、订单查看与个人中心。

### 3.2 产品目标

1. 建立旅游产品从后台维护到移动端展示、用户下单、后台处理订单的闭环。
2. 明确 Admin/App 分离的接口协议与登录鉴权路径。
3. 在设计稿缺失的情况下，为前后端 Agent 提供完整页面清单、数据模型、查询参数与验收标准。
4. 保持实现范围精简，只实现业务闭环所需功能，不扩展复杂营销、支付网关、RBAC 或第三方集成。

### 3.3 非目标

- 不接入真实在线支付，支付状态通过模拟支付接口更新。
- 不接入真实短信、微信授权、地图导航或第三方库存系统。
- 不实现菜单权限、动态路由权限、复杂审批流。
- 不修改默认工程目录名、技术栈、依赖版本。

## 6. 业务流程

### 6.1 管理员维护产品流程

1. 管理员登录管理端。
2. 进入分类管理，维护可用旅游分类。
3. 进入产品管理，新增产品，填写分类、标题、卖点、价格、库存、目的地、出发地、天数、主图、轮播图、行程说明、预订须知。
4. 产品保存为草稿或直接上架。
5. 上架产品在移动端首页/列表可见。

### 6.2 用户预订流程

1. 用户打开移动端首页，浏览 Banner、分类与推荐产品。
2. 用户进入产品列表，按关键词、分类、价格、出发日期、排序筛选。
3. 用户进入产品详情，查看行程与须知。
4. 用户点击立即预订；未登录时跳转登录。
5. 用户在订单确认页填写出行日期、人数、联系人、手机号、备注。
6. 系统创建待支付订单并扣减可售库存。
7. 用户点击模拟支付，订单变为已支付。
8. 管理员在后台确认订单，后续标记完成或取消。

### 6.3 订单状态流转

| 当前状态 | 操作方 | 动作 | 目标状态 |
|---|---|---|---|
| 待支付 `PENDING_PAY` | 用户 | 模拟支付 | 已支付 `PAID` |
| 待支付 `PENDING_PAY` | 用户/管理员 | 取消订单 | 已取消 `CANCELLED` |
| 已支付 `PAID` | 管理员 | 确认订单 | 已确认 `CONFIRMED` |
| 已确认 `CONFIRMED` | 管理员 | 完成服务 | 已完成 `COMPLETED` |
| 已支付/已确认 | 管理员 | 取消订单 | 已取消 `CANCELLED` |

  - `u-form`：账号、密码。
  - `u-button`：登录。
  - `u-toast`：错误提示。
- 行为：
  - 登录成功保存 token，返回来源页或进入首页。
  - 下单、收藏、个人中心访问时若未登录跳转登录。

#### 7.6.2 注册页

- 字段：账号、密码、确认密码、昵称、手机号。
- 校验：账号 4-32 位，密码 6-32 位，手机号格式合法，确认密码一致。
- 注册成功自动跳转登录页或直接登录。

#### 7.6.3 首页

- Layout：
  - 顶部搜索框。
  - Banner 轮播。
  - 分类宫格。
  - 推荐产品列表。
- Components：
  - `u-search`：点击进入产品列表并带入关键词。
  - `u-swiper`：展示启用 Banner。
  - `u-grid`：展示启用分类。
  - 产品卡片：主图、标题、目的地、价格、销量。
- 行为：点击分类进入产品列表并带 `categoryId`；点击产品进入详情。

#### 7.6.4 产品列表/搜索结果页

- 查询条件：
  - `keyword`：标题/目的地关键词。
  - `categoryId`：分类 ID。
  - `destination`：目的地。
  - `priceMin`、`priceMax`：价格区间。
  - `travelDate`：期望出行日期。
  - `sortBy`：`default`/`price`/`sales`/`createTime`。
  - `order`：`asc`/`desc`。
  - `page`、`pageSize`。
- Layout：顶部搜索框 + 分类/排序 Tabs + 筛选 popup + 产品卡片列表。
- 空状态：使用 `u-empty` 显示“暂无符合条件的产品”。

#### 7.6.5 产品详情页

- 展示内容：图片轮播、标题、副标题、目的地、出发地、价格、库存、销量、行程安排、费用说明、预订须知。
- 底部操作：收藏/取消收藏、立即预订。
- 行为：
  - 收藏需登录。
  - 立即预订需登录且产品上架、有库存。
  - 点击立即预订进入订单确认页并携带 `productId`。

#### 7.6.6 订单确认页

- 字段：出行日期、购买数量、联系人姓名、联系人手机号、备注。
- 价格计算：`totalAmount = product.price * quantity`。
- 校验：库存充足、出行日期不早于当前日期、联系人与手机号必填。
- 提交成功进入订单详情页。

#### 7.6.7 订单列表页

- Tabs：全部、待支付、已支付、已确认、已完成、已取消。
- 卡片字段：订单号、产品主图、标题、出行日期、人数、金额、状态。
- 操作：待支付订单可支付/取消；其他状态可查看详情。
- 分页加载：下拉刷新、触底加载更多。

#### 7.6.8 订单详情页

- 展示：订单状态、订单号、产品快照、出行信息、联系人、金额、创建时间、支付时间、备注。
- 操作：
  - 待支付：模拟支付、取消订单。
  - 已支付/已确认/已完成/已取消：仅展示状态和详情。

#### 7.6.9 个人中心

- 展示：头像占位、昵称/账号、手机号、订单入口、收藏入口、退出登录。
- 未登录状态：展示登录按钮。

#### 7.6.10 收藏列表

- 展示收藏产品卡片。
- 支持取消收藏，取消后当前列表移除。
- 产品下架时展示“已下架”标签，禁止预订。

## 8. 接口清单

### 8.1 通用约定

- Base URL：`http://127.0.0.1:9294/sqx_fast`
- Header：除登录/注册外均传 `token: <token>`
- Content-Type：`application/json`
- 成功响应：`{ "code": 0, "msg": "success", "data": ... }`
- 失败响应：`{ "code": 非0, "msg": "错误提示", "data": null }`
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 日期格式：`yyyy-MM-dd`
- 金额单位：元，使用 decimal 字段，前端展示保留 2 位。

## 9. 数据模型

- `travel_user` 1:N `travel_order`

## 10. 后端实现要求

1. 采用 Spring Boot 2.6 + Maven + MyBatis-Plus。
2. 分层生成 Entity、Mapper、Service、ServiceImpl、Controller、BO/VO/DTO。
3. 登录接口仅校验账号密码并返回 token，禁止接入菜单权限、Shiro `@RequiresPermissions`、RBAC。
4. Admin 与 App Controller 路径分开：
   - Admin：`/sqx_fast/admin/**`
   - App：`/sqx_fast/app/**`
5. 订单创建需使用事务：
   - 校验产品存在、上架、库存充足。
   - 扣减库存。
   - 写入订单快照。
6. 订单取消需按规则回补库存：
   - `PENDING_PAY`、`PAID`、`CONFIRMED` 可取消并回补库存。
   - `COMPLETED`、`CANCELLED` 不可取消。
7. 所有分页列表需支持 PRD 中定义的筛选条件与排序参数。
8. 单元测试覆盖：登录成功/失败、产品查询、订单创建、库存不足、订单状态流转、鉴权缺失。

## 11. 前端实现要求

### 11.1 管理端

1. 使用 Vue 3 + Vite + Element Plus，不新增不必要依赖。
2. 统一封装 request，自动携带 Header `token`。
3. 路由守卫：除登录页外，无 token 跳转 `/admin/login`。
4. 列表页均包含筛选表单、重置、查询、分页、空状态。
5. 新增/编辑表单须做前端基础校验，并显示后端错误提示。
6. 图片字段可使用 URL 输入或默认上传组件占位，需预留正式上传接口位。

### 11.2 移动端

1. 使用 uni-app + Vue 3 + uview-plus，不新增不必要依赖。
2. 统一封装 request，自动携带 Header `token`。
3. 用户端页面组件使用 uview-plus 习惯：表单使用 `u-form`，弹窗使用 `u-popup`，Toast 使用 `u-toast`，列表加载使用 `u-loadmore`。
4. H5、微信小程序、App 端布局需避免使用仅 H5 可用的 DOM API。
5. 下单、收藏、个人中心入口需做登录拦截。
6. 列表页支持下拉刷新与触底加载更多。

## 12. 验收标准

### 12.1 架构验收

- 三端目录名必须为：
  - `e2e-autoprd-1781188447795-server`
  - `e2e-autoprd-1781188447795-admin`
  - `e2e-autoprd-1781188447795-app`
- 服务端端口为 9294，Context 为 `/sqx_fast`。
- 管理端端口为 5173，移动端 H5 端口为 8080。
- 不得修改默认架构依赖版本，不得从零重写工程。

### 12.2 鉴权验收

- `POST /sqx_fast/admin/auth/login` 可独立登录管理员并返回 token。
- `POST /sqx_fast/app/user/login` 可独立登录用户并返回 token。
- Admin/App 登录接口互不复用路径。
- 登录/注册接口不需要 token，且不接入菜单权限、Shiro `@RequiresPermissions`、RBAC。
- 非登录接口缺少 token 时返回未登录错误。

- 订单管理可按关键词、状态、产品、用户、出行日期、下单时间、金额、排序筛选；可查看详情、确认、完成、取消。
